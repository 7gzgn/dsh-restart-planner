# dsh-self-restart

> 让 **agent 自己**安排一次 DSH 重启：先把这一轮说完，再由一个**活过这次重启**的 helper 停掉宿主、原地拉起、体检、留下报告。

给 **DSH**（DeepSeek Harness）用的**自重启**插件。
装完插件要重启才生效、改了 `.js` 要重启才加载、宿主卡住了要重启才能救 —— 以前这些都得**干等用户动手**。现在它是一个工具调用。

**零依赖 · 纯本地 · 不联网 · 平时完全静默**（不常驻、不轮询、不占资源）

---

## 为什么会有这个（真实事故）

起因是**一件很小、但每天都发生的事**：

> 装完一个插件，它说"重启后生效"。
> 而**重启这件事，只有用户能干** —— agent 只能停下来，等人回来点一下。

那天我在一处被卡住：插件写好了、配好了、就差一次重启。我什么都做不了，
只能把「请你关掉再打开」写进回复里，然后等。

**"让 AI 自己重启自己"** 听起来像一句废话 —— 直到你意识到：

> 重启 = **杀掉正在执行这句话的进程**。

当前这一轮会被打断在半路，回复可能还没送到用户眼前。这就是这个插件要解决的核心问题。

## 它是怎么破的

三段式，把「一次自杀」拆成**三个互不相干的进程**：

| 阶段 | 谁在做 | 做什么 |
|---|---|---|
| **1. 排程** | 你（agent / 用户） | 调用 `self_restart` → 立刻返回。**这一轮还没结束，什么都还没发生。** |
| **2. 交接** | 插件（宿主里） | 算好"要杀谁、用什么命令拉回来"，把任务交给一个**在宿主进程树之外**的 helper，并等它回来报到 |
| **3. 动手** | helper（独立进程） | 先等 `delaySeconds`（让这一轮回复送达）→ 再等会话日志**落盘安静** → 停 → 拉 → 体检 → 写报告 |

关键在第 2 步：**helper 必须活过它自己杀掉的那棵进程树。**

### Windows 上为什么必须绕道 Explorer

这不是"保险起见"，是**实测出来的硬约束**：

- 桌面端的宿主是 Chromium 起的，**进程在一个 job object 里**。被杀时 job 一关，里面的成员**一起没** —— helper 如果也在里面，就没人把 DSH 拉回来了。
- 直接 `spawn(..., { detached: true })` 在 Windows 上还有第二个坑：**PowerShell 被 detached 起来后什么都不做**（进程秒退、退出码 0、脚本一行都没跑）。这是实测结论，不是猜的。

所以 Windows 上走的是：**生成一个 `.lnk`，让 `explorer.exe` 去启动 helper**。
Explorer 在 job 之外、在交互会话里，由它起的进程才能**活过这次重启**，也才能把窗口放回用户桌面上。
（拿不到 Explorer 时退化成普通子进程，并在报告里写明这是降级路径。）

## 用法

```
self_restart({ action: "schedule", reason: "装完插件要重载宿主" })
```

**调用完就把这一轮正常说完** —— 重启发生在你的回复送达之后。
下一轮回来时：

```
self_restart({ action: "status" })     // 体检 + 上一次重启的结果
self_restart({ action: "cancel" })     // 撤掉还没执行的那次
```

可选参数（都在工具 schema 里）：

| 参数 | 默认 | 含义 |
|---|---|---|
| `reason` | — | 为什么重启，写进报告，重启后能看见 |
| `delaySeconds` | `20` | 至少等多久才动手（留出回复送达的时间） |
| `quietSeconds` | `4` | 会话目录要静默这么久才认为"写完了" |
| `maxWaitSeconds` | `180` | 等安静的最长时限，到点就走 |
| `dryRun` | `false` | 只演算、写一份 dry-run 报告，**不杀不拉**；也不放出 helper |
| `relaunchCommand` | 自动 | 宿主被包装脚本启动、自动识别的命令不对时才需要 |
| `confirm` | `false` | **先问用户什么时候可以重启**，再按选择排程（见下节） |
| `confirmFallback` | `ask-later` | `confirm` 没人应答时怎么办：`ask-later`（再等 30 秒）/ `cancel` / `now` |
| `confirmTimeoutMs` | `90000` | 等回答的上限；超时按 `confirmFallback` 走，**不会无限等** |

### 重启也叫眨眼：先问一句再动手

装在这台机器上的 agent 想重启时，**要不要让用户决定时机**，是使用者的选择，不是插件的：

```
self_restart({ action: "schedule", confirm: true, reason: "装完插件要重载" })
```

用户会看到四个选项 —— **立刻 / 30 秒后 / 60 秒后 / 取消**：

- 选「立刻」也会**先把这一轮回复说完、会话日志落盘**再动手（约 3 秒的最小窗口）；
- 选「取消」就什么都不做（不排程、不放 helper）；
- **没人应答**时按 `confirmFallback` 兜底，默认是「再等 30 秒」——**绝不静默改成立刻**。

默认**不询问**（保持全自动，适合无人值守）。需要问的时候才传 `confirm: true`。

### 不带工具也能用（CLI）

```bash
dsh-self-restart status                 # 体检 + 上次报告
dsh-self-restart resolve                # 只算：会结束谁、用什么命令拉回来
dsh-self-restart schedule --reason "改完代码" --delay 20
dsh-self-restart schedule --dry-run     # 先看看要动什么
dsh-self-restart cancel
```

从 DSH 自己的终端里跑时，它会顺着父进程认出宿主；从无关终端里跑、或宿主形态特殊时，用
`--caller-pid <宿主 pid>` 指一下。

## 安全边界

这些不是文档里的客气话，是**代码里的分支**：

| 机制 | 作用 |
|---|---|
| `delaySeconds`（默认 20s） | 先把这一轮回复说完，再动手 |
| 等会话日志**静默** `quietSeconds` | 会话状态已落盘才停，尽量不丢内容 |
| `maxWaitSeconds` 封顶 | 不会无限等安静 |
| **应用自己先退出了 → 不重启** | 用户手动关掉了，就尊重这个动作，不擅自拉回来 |
| `cancel` | 任何时刻都能撤（helper 每 400ms 检查一次） |
| `dryRun` | 完整走一遍流程，最后一步不动手；**也不放出 helper** |
| helper 自排除 | 它算 killList 时**先把自己和自己那棵子树剔掉**，绝不自杀 |
| 只动这一棵进程树 | 只结束宿主进程树之内的进程，**不碰系统、不碰别的应用、不碰 C 盘** |
| 报告全程落盘 | 每一步都写 `last.json`，中途死了也能看出死在哪一步 |
| **目标必须被明确指认**（v0.2.0） | payload 既没有 `targetPid` 也没有 `callerPid` 时，helper **拒绝动手**，不再用「往上找应用顶层」去猜 —— 这条是拿真实事故换来的（见下） |
| **授权标记文件**（v0.2.0） | helper 做 `arm`/`run` 前要求状态目录里有 `.allow-real-restart`，由调用方在交接前写入。**为什么用文件而不是环境变量**：`arm` 要经过 Explorer + 生成的 `.lnk`，那一跳**不带调用方的环境** |
| **临时目录闸**（v0.2.0） | 状态目录落在系统临时目录时，`scheduleRestart` 直接拒绝 —— 测试不该把重启排到真宿主头上 |

> 为什么会有上面两条 v0.2.0 的闸：开发这个插件时，我在**活代码树**里跑测试，
> 而 helper 的祖先解析一路往上走，解出来的「应用顶层」就是我正在用的那个宿主 ——
> 于是「跑个测试」变成了**把用户的应用连着重启**。
> 教训写进了代码：**目标必须被明确指认，猜出来的目标一律不动手**。

## 重启之后你拿到什么

`~/.dsh/dsh-self-restart/last.json`（`self_restart status` 会渲染成人话）：

```jsonc
{
  "state": "ok",                 // ok / started-but-unhealthy / relaunch-failed / exited-early / canceled / dry-run / error
  "reason": "装完插件要重载宿主",
  "targetPid": 5976,             // 被停掉的宿主
  "relaunchCommand": "\"C:\\...\\DeepSeek Harness.exe\" --remote-debugging-port=9224",
  "newPid": 12345,               // 拉起来的新进程
  "idleMs": 11537,               // 动手前会话已静默多久
  "downtimeMs": 3120,            // 停机时长
  "killList": [ /* 一并结束的相关进程 */ ]
}
```

插件**平时一句话都不说**；只有在"本进程刚刚被它重启过"的 10 分钟内，
才会在系统提示里补一句 `⚠ 本进程刚刚由 dsh-self-restart 重启过`，提醒 agent 去核对结果并汇报。
—— **安静是常态，刚重启完是个例外。**

## 兼容性

- **声明范围（peerDependencies 显式区间）：`>=0.2.0-rc.2 <0.3.0-0`**，覆盖整个 0.2 线（含 0.2.0 正式版）。
  **下限 = 我实际验证过的版本，上限 = 下一个大版本** —— 没验证过的大版本不声称兼容。
- **运行时主动降级**：拿不到 `@deepseek-ai/dsh-tools` 的 `defineTool` → 退化成恒等函数；`ctx.systemPrompt` 没有 `section` → 跳过公告段；拿不到 `ctx.webServer.port` → 少一项健康检查（不报错）。宿主 API 有出入时，它**少一项能力，而不是把你整个 DSH 拖崩**。
- **平台**：

  | 平台 | 状态 |
  |---|---|
  | Windows + DSH 桌面端 0.2.0-rc.2 | ✅ 实测（真机重启验证，含"helper 活过自己杀掉的进程链"） |
  | Windows + `dsh web`（CLI） | ✅ 走同一套 helper（自动回退到普通子进程路径） |
  | macOS / Linux | ⚠️ 代码在 `lib/helper.mjs`，**没有在真机上跑过** —— 按本插件的诚实标准，标为未验证 |

- 依赖：Windows 侧用系统自带的 PowerShell（5.1 即可，纯 ASCII 脚本，不挑编码）；不需要管理员权限、不需要计划任务。

## 已知限制（诚实清单）

- **是"停"不是"优雅退出"**：桌面端的退出路径要么是托盘菜单、要么是确认对话框，**外部无法触发**，所以这里是对整棵进程树 `Stop-Process -Force`。会话内容靠"等落盘安静"来保护，但不能保证"最后 0.1 秒"的写入。
- **桌面端会关掉再打开**：窗口会消失几秒再回来（会话选择存在浏览器本地存储里，回来还是同一个会话）。
- **一次只排一次**：重复 `schedule` 会覆盖上一次的排程，不排队。
- **`dsh web` 从无关终端驱动时**，需要 `--caller-pid` 告诉它哪个才是宿主。

## 和别的"重启按钮"插件什么关系

市面上已有的重启插件，绝大多数是**给人按的**：网页角落一个按钮、设置页一个开关、托盘一个菜单。
这个插件的对象是 **agent 自己**：它把"重启"变成一个可以被**调用**的动作，并保证**调用者不会死于这次调用**。

两者不冲突 —— 用户想点按钮就点按钮，agent 需要重载时不用再喊人。
